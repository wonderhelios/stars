# 永续合约资金费率事件观察

本程序每 5 分钟扫描 OKX、Binance 和 Hyperliquid 永续合约，记录过去 24 小时价格涨跌超过 3%、预测资金费率高于 0.05% 的信号。每家交易所的同一合约、同一信号形态在 24 小时观察期内只记录首个信号；形态变化会作为新的研究样本保留。所有信号按做空方向观察 1、4、8、24 小时后的价格变化。网页和 OKX `paper report` 展示的净收益估算统一扣除 0.15% 往返交易成本，不包含实际资金费收入、真实成交滑点或强平影响，因此不是账户收益。

研究页会组合交易所、信号形态、持仓时间、止损和同时持仓上限，并按时间切分训练段与验证段。Hyperliquid 主 DEX 候选只有在总样本不少于 30、验证样本不少于 10、覆盖至少 5 个 UTC 日、验证中位数为正且盘中路径覆盖率不少于 80% 时，才可导出到 Hyper Fly 策略库；其他结果明确标为继续观察。研究页不会直接修改实盘机器人。相邻观察价格接近 `1:2`、`1:3`、`1:4` 等常见换算比例，或出现更大的尺度跳变时，该记录会作为疑似拆股、换算或合约调整排除出收益统计和候选排名，同时保留在原始信号明细中。

Hyperliquid 扫描每轮通过 `perpDexs` 发现主 DEX 和全部 HIP-3 DEX，不依赖静态部署者名单；若某个 DEX 请求失败，日志会记录失败和成功覆盖数。

## 五仓研究的数据采集

每轮扫描会把满足现有信号条件的**所有**候选写进各平台数据库的 `candidate_snapshots`，包括因 24 小时去重而没有新增到 `signals_v3` 的候选。`scan_runs` 只在本轮扫描正常结束时写入；做跨平台研究时应连接这张表，并优先使用 `failed_count = 0` 的轮次。两张表会随现有服务自动创建，不改变网页信号统计。

快照记录扫描开始时间、该候选实际观察时间、信号类别、参考价、费率及结算周期、下次结算时间、24 小时成交额、买卖盘价格和报价时间。OKX、Binance 的报价为最优买卖价；Hyperliquid 的 `quote_kind = impact` 是交易所提供的冲击买卖价，不能当成最优盘口，也不能直接视为 500 美元的可成交价。缺失的字段保持 `NULL`，不要用零填充。三个数据库仍分别使用 `OKX_QUANT_DB`、`OKX_QUANT_BINANCE_DB`、`OKX_QUANT_HL_DB` 指定的文件。

例如检查最近已完成的扫描及其快照数量：

```bash
sqlite3 -header -column /var/lib/okx-quant/hyperliquid.sqlite \
  'SELECT datetime(r.scan_started_at/1000,"unixepoch") AS scan_utc, r.market_count, r.prefiltered_count, r.recorded_count, r.failed_count, COUNT(c.inst_id) AS stored FROM scan_runs r LEFT JOIN candidate_snapshots c USING (scan_started_at) GROUP BY r.scan_started_at ORDER BY r.scan_started_at DESC LIMIT 5;'
```

三平台的扫描仍错开启动，因此复盘时须按候选的 `observed_at` 和报价时间对齐，并限制快照年龄；不能再按旧信号触发时间简单地“先到先得”。候选快照目前只记录决策时可见的信息，尚未记录所有候选的未来退出价格或实际资金费流水。

## 重新部署

### 研究页的全市场信号实验

OKX、Binance、Hyperliquid 三个平台的研究页均对本平台**所有已记录的信号**逐笔独立计算。Hyperliquid 扫描范围包括主 DEX 和动态发现的 HIP-3 DEX。研究实验没有本金、同时仓位或杠杆档位限制，也不设单仓美元止盈，因此可以观察实盘因为资金和仓位规则没开出的币对。原采集条件仍要求 24 小时价格异动、正资金费率和至少 50 万美元的 24 小时成交额；这不是对所有挂牌合约无条件产生交易信号。

实验并列比较 2%、3%、5% 三种价格逆向止损。新版部署后，OKX 和 Binance 每分钟、Hyperliquid 每轮扫描更新未到期信号的路径高低点，并保存三个止损阈值首次被观察到的时间；旧记录没有路径数据时才回退到 T+1、T+4、T+8、T+24 定点检测。触发止损按阈值价格估算退出，未触及的使用对应持仓期限价格。三组使用相同信号样本和固定 0.15% 往返成本，显示触线次数、净胜率、单笔净收益均值、中位数和等权收益合计。实际成交滑点、采样之间的瞬时波动、资金费和强平仍无法完全还原；这是研究回放，不是账户收益。

同一批信号还会按触发时间先到先得，比较最多同时持有 1、3、5 仓时的结果，并与三档止损交叉展示。每仓按相同名义金额理解；采样止损后释放仓位，未止损则占用 24 小时。该容量实验不模拟账户余额、杠杆差异、复利或实盘的单日风控，结果用于判断有限仓位是否仍能保留信号优势。

研究页还会把交易所、四种信号形态、1/4/8/24 小时持有期、无止损或 2%/3%/5% 止损、1/3/5 仓上限自动组合。每组按时间切成前 70% 训练段和后 30% 验证段，候选榜以两段单笔均值的较低者排序；这只能降低直接看全样本挑参数的偏差，仍存在多重测试和小样本风险。三平台相同底层币种在 15 分钟内共同触发的信号也会单独汇总，用来检查方向优势是否能跨平台复现。

为研究市场中性的资金费率策略，服务会从部署新版开始按 UTC 小时保存三平台全市场快照，包括费率、真实结算周期、参考价、报价、成交额和未平仓量（交易所提供时）。每小时只保留最新一轮，自动保留 90 天；成交额低于 10 万美元的市场不写入。页面只展示双腿成交额均至少 50 万美元的同币种候选，将费率统一换算为 APR，并估算双腿固定成本和当前报价摩擦的回收时间。这个区域在积累历史快照前只是实时候选扫描，不会把预测费率差冒充已实现套利收益。

从现在起，Hyperliquid 候选快照还会记录当时的最大杠杆和数量精度。旧快照没有这些字段，也没有盘中的标记价格和完整 L2 盘口，因此无法精确回放旧信号的 2% 止损及实际成交。

```bash
cargo build --release
```

默认服务监听 `0.0.0.0:3000`。数据库路径可用 `OKX_QUANT_DB`、`OKX_QUANT_BINANCE_DB`、`OKX_QUANT_HL_DB` 指定；默认分别位于 `/var/lib/okx-quant/` 下。请确保运行用户可写。三个数据库现在都使用统一的 `signals_v3` 表；旧表不会进入新统计。建议重新部署前备份旧数据库，并在需要全新数据文件时换用新路径。

记录的入场价是扫描时读取的行情价，不是实际成交价。到期价格取在目标时刻或之后最先收完的 1 分钟 K 线收盘价，最多比目标时刻晚 1 分钟。交易所接口暂时不可用时会重试；仍失败的价格留空，后续跟踪会再次尝试。

网页请求短暂失败时会保留浏览器中上次成功的数据，并明确显示断线状态和最后成功时间。HTTP 502 通常还需要检查网关与应用服务之间的连接，以及服务器上的服务日志；前端保留旧数据不代表行情仍在更新。

如果只有访问网页时偶发 502，先从访问网页的电脑对比普通请求和绕过本机代理的请求：

```bash
curl -sS -o /dev/null -w '%{http_code} %{time_total}\n' http://8.219.113.154:3000/api/snapshot
curl --noproxy '*' -sS -o /dev/null -w '%{http_code} %{time_total}\n' http://8.219.113.154:3000/api/snapshot
```

直连正常而普通请求失败时，应在本机代理规则中让服务器 IP 直连。服务器位于海外并不代表浏览器访问它时会自动绕过本机代理。OKX 行情响应启用了 gzip 压缩，以减少传输时断流的机会。

OKX WebSocket 若超过 90 秒没有收到任何有效行情，会主动断开并重连；若重连后仍无新行情，请检查服务日志里的 `okx ws` 错误以及服务器到 `ws.okx.com:8443` 的连接。

## 历史研究

```bash
cargo run --release -- research BTC-USDT-SWAP ETH-USDT-SWAP
cargo run --release -- research scan 200
```

历史研究优先使用**实际结算**资金费率，缺失时回退到历史预测费率，在结算后一小时的 K 线开盘价模拟入场。同一合约、同一费率方向的历史事件也按 24 小时去重。这只是探索性事件研究，与实时扫描预测资金费率并立即记录价格的规则不同。`scan` 根据**当前**报价金额选币种，不能消除历史币池偏差。其做空超额数字不能直接视为可交易 alpha；判断策略仍需按事先固定规则、独立后续数据、实际成交成本与同时间基准验证。不同交易所的同一底层币种仍可能同时出现，在跨交易所汇总时应按币种和时间聚类，而不是当作相互独立的交易。


## 执行证据与策略交接 v2

探索表的单笔均值和等权收益合计仍用于筛选研究方向，不能直接当作账户收益。新的“执行回放”使用与 Hyper Fly 相同的 Rust 规则库，重现候选跨入、基线、冷却、优先级、杠杆上限、每次净值 20% 保证金与合约精度；通过真实采样盘口估计入场和退出，不用止损线冒充成交价。分钟采样仍可能遗漏短时波动，实际成交、部分成交和真实费率无法完全复制。

后台从新版部署开始记录 `execution_frames`：全市场元数据、每个 DEX 的成功覆盖情况、信号合约的 L2 盘口。候选离开条件后继续跟踪 24h，数据保留 30 日。回放逐行读取独立 WAL 快照，避免将一个月的数据载入内存或阻塞行情写入。旧 T+1h / T+24h 数据不能补出不存在的完整路径。

研究页点“执行回放”后可“保存候选到策略库”，后台再次计算证据，然后通过本机接口写到 Hyper Fly 的策略库，不需要下载上传。未通过候选可运行独立模拟；启用实盘前还需历史样本、时间验证、完整价格 / 盘口证据，以及至少 48h / 10 笔独立模拟。Hyper Fly 必须同步更新，两份规则源码和策略参数摘要都要相符。

当前可交接 Hyperliquid 主 DEX 和 USDC 抵押的 HIP-3 单腿价格做空策略。跨平台同币统计和费率候选仍保留在研究页；OKX / Binance 下单、跨平台确认条件及双腿对冲没有执行适配器，页面明确显示不可交接。模拟不计正费率收入，对观测到的负费率计成本预留；不是实际资金费流水，因此不能用于验证费率套利收益。统计门槛不等于已找到 alpha。

查看新数据是否持续写入：

```bash
sqlite3 -header -column /var/lib/okx-quant/hyperliquid.sqlite \
  'SELECT datetime(at/1000,"unixepoch") AS frame_utc FROM execution_frames ORDER BY at DESC LIMIT 5;'
```
