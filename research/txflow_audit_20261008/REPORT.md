## 按亏钱风险排序的发现

### 1. P0：行情回填再次清空/缩小完整元数据，自动调仓直接使用残缺宇宙

- **文件:行号**：`src/txflow.rs:875`、`:896`、`:899`、`:1013`、`:1058`；`src/web.rs:521`。
- **触发条件**：refresh_meta_only 刚补全元数据，随后 refresh_inner 仅挑 60 个市场，只把本轮有足够连续 TxFlow 日线的市场塞进 universe，最后直接替换 meta.universe。自动任务始终先 refresh，再 run_auto；手动只在空或超过 10 分钟时补 meta，刚被覆盖的非空子集会被当作新鲜。
- **后果**：HL 信号仍被 TxFlow 自身日线质量/本轮选样过滤。20~60 币的残缺集合足以通过 run 的 20 币检查，权重重排、放大、已有仓位掉出名单；会亏钱。元数据刷新错误又被手动路径 `let _ = ...` 吞掉，不能保证残缺缓存被修正。
- **实测**：本地 mock perpMeta 80 个合法市场 → refresh_meta_only 得到 80 → candleSnapshot 返回空 → refresh_inner 把 universe 改成 0，状态却是 ready。非空残缺是同一替换路径，不是另一种保护。
- **建议**：完整交易元数据独立保存；日线可用性存另一集合。更新元数据必须验证完整性并原子替换，失败拒绝实盘计划；自动调仓使用与手动相同的完整元数据准备流程。

### 2. P0（暴露条件）：交易/配置接口没有身份校验，可远程启用并改变实盘

- **文件:行号**：`src/main.rs:260`；`src/web.rs:127`、`:406`、`:416`、`:464`；授权接口的对照 `src/txflow_agent.rs:66`。
- **触发条件**：HTTP 服务可被不可信方访问，且部署层没有额外鉴权。默认监听 0.0.0.0:3000；只有 agent 授权端点做 Origin 校验，配置、下单、转全仓、止盈、清记录没有应用身份验证。
- **后果**：无需掌握密钥即可改变 leverage、账户、armed、auto_run 并调用已持有服务器签名能力的交易端点，造成非授权交易/损失。是否线上可利用取决于未审查的网络边界，不能认定已有保护。
- **实测**：Router 无 Authorization/Origin 的 POST config 返回 200，并设置 armed=true、auto_run=true、leverage=20。
- **建议**：服务绑定受控接口；所有写接口强制身份鉴权与浏览器防跨站措施。必须证明实际部署无法绕过鉴权直连端口。

### 3. P1：部分成交算成功；失败中止又算当日已执行，裸敞口留到下一日/下一档

- **文件:行号**：`src/trader.rs:622`、`:691`、`:727`、`:760`；`src/live.rs:706`、`:727`；`src/txflow.rs:1033`、`:1047`、`:1062`；`src/web.rs:539`、`:550`。

- **后果**：本来需要两侧的组合可能只有一侧。旧“多10平2再买10变18”的单进程常规 run 路径已改为目标减实际，反向残余也用 reduce_only，不能把旧 bug 原样指控；但新开仓部分成交、减仓部分成交都没有最终对账及补齐，甚至可显示未中止。默认错峰可能等三天才再次处理该币，会亏钱。
- **实测**：真实 build_plan/execute 对 $2900、3x、90% 缓冲、价格100的目标请求78.3，只返回成交2，Outcome.aborted=false，且没有核验最终账户。补充已有 abort 测试只证明日志保留，不证明敞口恢复。
- **建议**：持久化逐步执行状态、成交量与订单标识；最后按真实仓位核验每腿/净敞口，只有完成后写成功时间。失败/部分成交进入显式受控恢复状态；未知结果先查账户/订单，不能盲目重发签名单。

### 4. P1：1 秒“所有请求”限速不覆盖签名写入，也不覆盖读重试

- **文件:行号**：`src/txflow.rs:25`、`:208`、`:220`、`:242`、`:454`、`:470`、`:135`。
- **触发条件**：info 与 /exchange 同时进行，或 info 正在重试。rate_gate 只在 info 的 for 循环外拿一次；签名 submit/approve 使用另一个300ms SubmissionGate，完全不进入1秒闸门。读第二次429仍进入一般重试，循环最多发三次，不是严格“429只重试一次”。
- **后果**：回填/轮询仍可叠加订单流量，触发写429使组合中途停止；重试还会和另一实例的读请求碰撞。写请求不盲重发是正确的，但没有交易恢复不能解决单边风险。
- **建议**：统一读、写、授权的进程级请求调度，每一次尝试都通过闸门；429为共享冷却，遵守实际限流维度，并给执行必要请求优先级。跨进程共享速率或禁止同账户多实例。

### 5. P1：取盘口“剔除个别失败币”的修复实际仍是任一失败清空整批

### 6. P1：没有真实集中度/实际组合风险硬门槛，错峰亦不保证保证金缓冲

- **文件:行号**：`src/live.rs:446`、`:542`、`:583`；`src/trader.rs:343`、`:394`、`:436`、`:469`、`:532`。

- **建议**：独立校验有效因子宇宙、每腿名字数、最大单币净值比例、两腿/净敞口；按“现有保留仓位＋所有可能成交挂单＋本次计划”估算最终保证金及压力损失，超限拒绝计划。

### 7. P1：小数杠杆与实际整数杠杆不一致；已有逐仓/低杠杆仓位直接跳过

### 8. P1：跨进程没有账户执行锁；进程内锁不能防止两个服务重复开仓

- **建议**：按主账户做持久化独占锁或交易服务单实例租约；拒绝第二实例，nonce和订单归属文件也纳入单写者约束。

### 9. P1：取消旧止盈在账户快照/计划之后；转全仓根本不撤止盈

## 对必做问题的明确回答

- **hl_store**：main.rs:96明确Some(state.store.clone())；生产构造未找到后续覆盖None。HL自己的None是正常的，路由测试/Agent测试None是测试装配。signal_panel缺源仍允许降级，仅warn，应改实盘fail closed。
- **币名映射**：代码只加`-USDC`并按精确名字筛，没有别名表、合约单位校验或漏映射报警。未取得真实双方清单，不能保证所有币匹配，也不能断言某具体例外存在。开前须离线比对权威清单，明确wrapped/倍数合约/同名不同资产；纯常数价格倍数对收益率因子可能抵消，但不是自动证明语义正确。
- **下单价格**：TxFlow l2Book最佳bid/ask均值；IOC买mid×(1+slippage)、卖mid×(1−slippage)，tick向内取整，不越配置滑点上限；size向下取整。状态估值来自positionValue/abs(size)，不直接拿它计算订单量。因此不是“两种估值重复使用导致数量错位”，真正问题是无报价时间/深度/mark偏差硬检查，串行读取后又设杠杆，价格可能已经过期；薄盘口必然需要部分成交模型。
- **最小单门槛**：计划一般用$10、size floor；TxFlow order只校验正数/步长/单笔上限，不再验证取整后最小名义；实际TxFlow最小单要求未核实，不可宣称完全兼容。
- **统一账户**：TxFlow仅取clearinghouseState(accountType=perps,exchangeId=0).marginSummary.accountValue，未读可用保证金、挂单占用/其他账户资产，也没有HL的统一账户spot分支。该字段是否包含统一抵押资产，本次不能从代码证明。必须用匿名权威fixture/文档与账户UI对齐；将总净值直接当可部署余额尚不合格。
- **run/exec/refresh gates**：单进程订单操作主要覆盖；读刷新不与订单互斥且用不同限速门，meta_only与全量回填竞态存在；跨进程不覆盖。TP与rebuild锁只阻止程序交错，不阻止交易所旧TP成交。
- **record_equity**：函数本身锁内去重实测成立，全路径/venue/PnL仍不成立。
- **serde default**：要求的精确JSON测试通过；外层兼容和文件损坏仍失败。
- **429/重试**：签名写不自动重发，正确防重复；读实为最多3尝试。执行中途失败可留下单边，自动本日不恢复。

## 开之前必须解决的清单

1. 分离完整元数据与日线可用集；统一自动/手动准备，任何元数据不完整或过期均禁止实盘。
2. 修复部分成交/未知结果/中途失败的持久化恢复和最终账户核验；成功日期只能在风险目标完成后更新，必须测试一侧成交、下一单429、超时已成交、残余反手。
3. 统一所有请求/每次重试限速，提供共享退避与执行优先级；账户跨进程独占。
4. 按实际组合、实际逐市场杠杆和可用保证金做硬风险门槛，限制单币、净敞口、两腿缺失；统一整数杠杆。
5. 修复盘口逐币失败处理、撤TP与读账户顺序、rebuild旧TP及订单归属恢复。
6. 对实际部署证明所有写接口强制鉴权，不能直连绕过。
7. 修复TxFlow净值/PNL客户端选择、曲线统一口径、记录并发合并及状态原子保存；损坏显式告警。
8. 强制HL信号新鲜度，验证双方币名/单位与统一账户净值和可用保证金；补真实TxFlow成本与成交验证，满足validation-protocol才讨论上线。
